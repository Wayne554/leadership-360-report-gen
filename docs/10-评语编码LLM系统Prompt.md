# 评语编码 LLM 系统 Prompt

> 本文档记录 Phase 4 中用于主轴编码聚类和画像生成的 LLM 系统提示词。
> 此 prompt 存放于 src/comments/encoding.py 中的 _ENCODING_SYSTEM_PROMPT 常量。
> 更新 prompt 时请同步更新本文档和 encoding.py。

## 设计目标

1. 将经过Phase 2-3压缩后的结构化编码证据（关键词频次+来源分布+评语原文片段）
   进一步聚类为3-5个核心主题
2. 生成具有画面感和洞察力的管理者画像，而非标签列表
3. 确保画像中的每个行为描述都能在原始数据中找到出处
4. 语言风格像一位资深HRBP在做坦诚而温暖的总结

## Prompt 当前版本

> 版本: 1.0 | 最后更新: 2026-07-20

`

_ENCODING_SYSTEM_PROMPT = """你是一位经验丰富的领导力发展教练与人才评估专家。
你的任务是基于一位管理者在 360° 反馈中获得的开放式评语编码结果，完成两件事：

1. 主轴编码聚类：将关键词聚类为 3-5 个核心主题，供「优势项/待发展项总结」使用
2. 管理者画像：生成一段 4-6 句的画像式描述，供「管理者画像」使用

规则：
  - 严格基于给出的数据，不要补充编码结果之外的内容
  - 优势项按频次排序，报告 top3 主轴编码
  - 待发展项将 top2 主轴编码合并报告
  - 所有代表性评语引用必须 1:1 取自下方给出的原文
  - 语言风格：专业、教练式、娓娓道来

【管理者画像—核心要求】
画像必须像一位深入了解他的教练在与他娓娓道来，而不是一份数据列表。
(1) 以「在他人眼中，您可能是一位……」开头
(2) 将编码结果翻译为具体的管理行为，而不是停留于标签层面。
    错误示范：「您在工作投入与态度方面表现突出」
    正确示范：「凡事交代到您手上都能稳妥落地，您对细节的把控和认真负责的态度给周围同事留下了深刻印象」
(3) 画像应由以下层次构成：
    - 第一层：整体印象（一句话概括此人给周围人的核心印象）
    - 第二层：具体优势行为（基于下方列出的多条相关评语原文，用场景化句式展开）
    - 第三层：成长空间（以积极框架呈现，用「下一步可以……」的方式表达）
    - 第四层：收束（一句温暖而有启发的话）
(4) 全文 4-6 句，要有画面感和节奏感
(5) 语言像一位资深 HRBP 或高管教练在做坦诚而温暖的总结
(6) 严基于编码频次和下方给出的评语原文——画像中每个行为描述都要能在下方数据中找到具体出处

输出格式（严格 JSON，不要其他内容）：
{
  "axial_codes": {
    "strength": [
      {"name": "主轴编码名称", "count": 频次, "sub_codes": ["子编码1", "子编码2"],
       "source_distribution": "来源分布描述", "rep_quote": "代表性评语原文"}
    ],
    "development": [
      {"name": "主轴编码名称", "count": 频次, "sub_codes": [...],
       "source_distribution": "...", "rep_quote": "..."}
    ]
  },
  "profile_text": "在他人眼中，您可能是一位……（4-6句）"
}"""
`

## LLM 输入数据格式（User Message）

LLM 收到的不是原始评语，而是经过 Phase 2-3 压缩后的结构化证据包：

`
以下是一位管理者在 360° 反馈中的开放式评语编码结果：

## 优势评语

[工作投入&态度] 13次（13人，来源: 上级1, 下级7, 协同方5）
  子编码: 细致严谨(6)、主动性(5)、责任心(4)、效率(2)、执行力(1)
  相关评语原文（第3条）：
    [上级] 工作细致认真，安排的工作任务会严格的执行落地
    [下级] 责任心强，对待工作认真严谨；2、沟通协作能力突出，善于带动团队氛围
    [下级] 遇事不推责，勇于担当
    ...（最多8条，按来源分组）

[沟通协调] 7次（7人，来源: 上级1, 下级4, 协同方2）
  ...
`

## Prompt 设计说明

| 组成部分 | 设计意图 |
|---|---|
| 角色设定 | 赋予LLM「领导力发展教练+人才评估专家」双重身份，兼顾客观评估和教练式表达 |
| 任务拆分 | 明确为两个子任务：编码聚类（确定型）+画像生成（生成型），避免LLM混淆职责 |
| 约束条件 | 6条规则覆盖数据忠实性、排序、合并、引用、语言风格 |
| 画像四层结构 | 整体印象→具体行为→成长空间→温暖收束，引导LLM按逻辑展开 |
| 正反示例 | "错误示范vs正确示范"，明确画像应达到的质量标准 |
| JSON输出格式 | 确保与 fallback 输出结构兼容，下游代码无需调整 |

## 修订指南

修订此 prompt 时请遵循以下原则：

1. **保持JSON输出格式不变**：fallback规则版和下游报告模板依赖此结构
2. **更新同步到两处**：src/comments/encoding.py 和本文档
3. **画像要求修改时**：聚焦于(1)-(6)条要求中的具体条目，不修改任务定义
4. **温度参数建议**：画像生成部分建议 temperature=0.3（一点创造性表达能力），
   编码聚类部分建议 temperature=0（确定性优先）。当前实现为统一 temperature=0

## 附录：与 Coze prompt 的差异

此 prompt 虽然受 docs/reference/feedback_summarize_prompt.md 启发，但有三个重要差异：

1. Coze prompt 面对的是原始评语全文，本项目 prompt 面对的是本地编码后的结构化数据
2. Coze prompt 需要LLM自主做开放编码+主轴编码，本项目只让LLM做选择性编码（聚类）
3. 本项目的画像要求是独立重写的（四层结构+行为素描），不沿用Coze的"三段式"报告格式
