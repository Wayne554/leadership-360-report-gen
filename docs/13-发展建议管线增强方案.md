# 发展建议管线增强方案

> 本文档记录了"个性化 + RAGFlow 知识库驱动的发展建议"的架构设计。
> 目标是将当前"预写举措 + RAG insight/quote"的模式，升级为**基于评语编码关键词 + 经典领导力书籍知识库，由 LLM 全量合成个性化发展建议**的模式。

---

## 背景与动机

当前管线的三个困惑和我们的分析：

### 现状

生成个性化发展建议的三条数据流入

```
_encoded.json（评语编码 Phase 1-4）          dev_config.json（预写举措库）
│                                            │
│  axial_codes: strength + development        │  6 维度 × 5 条行为化举措
│  profile_text: 管理者画像                    │  （所有人通用，不个性化）
│  sub_codes: 评语关键词频次                    │
       │                                            │
       └────────── ─ ─ ─ ─ ─ ─ ─ ┘
                       │
                       这两个数据流在 LLM 合成器中**未交汇**
                       │
                       ▼
                当前 LLM 只生成 insight + quote（依赖 RAG 知识库）
                建议举措（actions）来自预写库，千人一面

RAGFlow 知识库
│  SMH / FYI / Army Handbook
│  经典领导力发展内容
       │
       ▼
   rag_context → LLM → insight + quote ✅
                但 actions ❌ 未个性化
```

### 需求

> 发展性建议应当是：
> 1. **Solid**——来自已验证的经典领导力发展书籍（SMH、FYI、Army Handbook 等知识库）
> 2. **个性化**——基于完整的开放式评语编码所提取的关键词（axial_codes、sub_codes）

---

## 目标架构

```


评语编码 Phase 1-3 → axial_codes / sub_codes / 频次分布     RAGFlow 知识库
                     ↓  per person                          ↓  SMH / FYI / Army
                prepare_context.py                          prepare_context.py
                     ↓                                        ↓
               comment_profile 增强                           rag_context
               （当前为空，需注入）                                |
                     └──────────────────┬──────────────────────┘
                                        ▼
                              llm_synthesizer.py
                              SYSTEM_PROMPT 增强
                              per dimension 生成:
                                1. insight（发展洞察）
                                2. actions（行为化举措）✅ 新增
                                3. quote（引语）
                                        │
                                        ▼
                              rag_suggestions_{uid}.json
                              （含新增的 actions 字段）
                                        │
                                        ▼
                              dev_suggestions.py
                              hybrid 模式 → 优先使用 LLM 生成的 actions
                              static 模式 → 回退到 dev_config.json 预写举措
```

---

## 改动方案

### 1. prepare_context.py — 数据注入（~25 行）

当前 `rag_context["comment_profile"]` 三个字段全为空。需要：

- 在 `load_person_eval()`（或同级别入口）加载 `_encoded.json`
- 提取以下数据写入 `comment_profile`：

```python
{
  "profile_text": "在他人眼中，您可能是一位…（来自 Phase 4 LLM 画像）",
  "axial_codes": {
    "strength": [
      {"name": "工作投入&态度", "count": 13, "sub_codes": ["细致严谨", "主动性", ...]},
      ...
    ],
    "development": [
      {"name": "业务&技术能力", "count": 8, "sub_codes": ["业务经验", "专业能力", ...]},
      ...
    ]
  },
  "top_keywords": ["细致严谨", "责任心", "沟通表达", ...],
  "development_keywords": ["跨部门协作", "业务经验", "方案能力", ...]
}
```

### 2. llm_synthesizer.py — 输入增强 + Prompt 修改 + 输出扩展（~40 行）

**输入增强**：在构造 LLM 调用时，从 `rag_context["comment_profile"]` 读取关键词和画像文本，格式化为上下文文字送入 LLM。

**SYSTEM_PROMPT 修改**：当前仅要求生成 insight + quote，需要增加第 2 项产出：

```
生成内容：
1. insight（发展洞察）：一段 3-5 句的教练式引导文字，结合参考内容和评语关键词进行有温度的启发
2. actions（行为化举措）：基于参考内容和评语关键词，为该管理者生成 3-5 条个性化的行为化发展举措
3. quote（引语）：从参考内容中选取一句最相关的原文作为引语，注明出处
```

**输出格式扩展**：

```json
{
  "dimensions": {
    "维度名": {
      "insight": "…",
      "actions": ["举措1", "举措2", "举措3"],
      "quote": "——《来源书名》"
    }
  }
}
```

### 3. dev_suggestions.py — 消费端适配（~20 行）

- `_load_rag_suggestions()` 新增 `actions` 字段的读取
- `get_development_section()` 中 hybrid 模式：如果 LLM 为该维度生成了 `actions`，优先使用 LLM 版；如果 `actions` 字段不存在或为空，回退到 `dev_config.json` 预写举措
- static 模式：不变，仍然使用 `dev_config.json`

---

## 改动影响

| 维度 | 影响 |
|:---|:---|
| `rag_context` 增量 | 文件体积增加 ~1-2KB（comment_profile 数据） |
| `rag_suggestions` 增量 | 每维度增加 actions 数组，约 0.5KB |
| LLM 调用价格 | 同一次调用，input token 增加 ~200-500（关键词+画像），output token 增加 ~100-200（措施文本），总成本增加 ~20% |
| LLM 响应时间 | 略有增加，估计 5-8s → 7-10s |
| 降级兼容性 | static 模式完全不变；hybrid 模式对旧格式兼容（无 actions 字段时自动回退） |

## 执行计划

### Phase 0 — 代码修改（~2 小时）

| 步骤 | 文件 | 内容 |
|:---:|:---|---|
| 0.1 | `prepare_context.py` | 注入编码数据到 comment_profile，确保 `rag_context` 携带关键词+画像 |
| 0.2 | `llm_synthesizer.py` | 将 comment_profile 格式化为 LLM 输入上下文 |
| 0.3 | `llm_synthesizer.py` | 修改 SYSTEM_PROMPT，增加 actions 产出 |
| 0.4 | `dev_suggestions.py` | hybrid 模式加载 LLM 生成的 actions |

### Phase 1 — 单用户验证（~15 分钟）

选一个已知用户（如 10005728），跑通：

1. `prepare_context.py --user_id 10005728` → 确认 `rag_context.comment_profile` 有数据
2. `llm_synthesizer.py --user_id 10005728` → 确认 `rag_suggestions` 含 `actions` 字段
3. `generate_report.py --user_id 10005728` → 确认报告中的建议举措已个性化

### Phase 2 — 全量执行（~5-9 小时，可后台批量）

1. 全量 `prepare_context.py --all`（~50-90 分钟）
2. 全量 `llm_synthesizer.py --all`（~60-90 分钟）
3. 全量 `generate_report.py --all`（~10-15 分钟）

---

## 风险与缓解

| 风险 | 缓解 |
|:---|:---|
| LLM 生成的 actions 质量不可控 | 保留 `dev_config.json` 作为降级，Phase 1 验证时检查 2-3 份样本 |
| comment_profile 数据量过大致 token 飙升 | 只传递 top keywords（前 10-15 个即可），不到 axial_codes 完整 JSON |
| 现有 rag_suggestions 兼容性 | 读取时增加 `get("actions", None)` 默认值，旧文件自动降级 |
