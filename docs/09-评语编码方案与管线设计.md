# 评语编码方案与管线设计

> 本文档记录开放式评语的编码方法论、管线架构、关键设计决策。
> 相关文件：08-数据分析规范与方法论 · 03-常模构建方案 · 05-个体报告生成方案

## 1. 背景与动机

360° 反馈问卷中的开放式评语包含丰富的定性信息，是被评价人了解自身领导力形象的关键来源。
然而，原始评语存在三个问题：
1. 信息过载：每人 15-28 条评语，难以直接消化
2. 模式隐含：哪些能力被多人同时提及？评价来源之间是否存在差异？
3. 来源混杂：自评与上级/协同方/下级的评语交织，无法区分视角

因此需要一套系统化的编码方案，将定性文本转化为结构化、可审计的编码结果，
再通过 LLM 的聚类和语言能力生成有洞察力的管理者画像。

## 2. 方法论：基于扎根理论的两级编码

编码方法采用扎根理论的两级编码技术：

| 编码层级 | 方法 | 本项目的实现 |
|---|---|---|
| 开放编码 | 从原文提取关键词/短语 | 本地关键词词典匹配，每个触发词为一个开放编码 |
| 主轴编码 | 将开放编码聚类为高阶类别 | 预定义6个编码视角，按视角聚合关键词 |
| 选择性编码 | 提炼为3-5个核心主题 | LLM跨视角聚类，产生报告呈现的最终编码 |

与经典扎根理论的区别：编码视角是自上而下预设的（基于领导力模型的6个维度），
而非自下而上涌现。这是出于360度反馈的评价内容天然落在这些维度内的实用性考虑。

## 3. 管线架构：Phase 1-4

src/comments/
  init.py — 模块入口
  config.py — 关键词词典 + 噪声过滤规则
  preprocess.py — Phase 1: 数据准备
  keywords.py — Phase 2: 开放编码+关键词提取
  selection.py — Phase 3: 关键词密度法选代表性评语
  encoding.py — Phase 4: 主轴编码+画像（LLM+fallback）
  pipeline.py — 统一入口：run_all()/run_one()

### Phase 1: 数据准备（preprocess.py）
从原始_rev.csv重构评语与评价来源的对应关系：
- 按被评人工号+关系列分组，恢复来源归属
- 剔除自评，不纳入他评分析
- 噪声过滤：丢弃单字符无意义内容
- 按3个评语类型分离：优势/发展/其他
输出：data/processed/comments/{person_id}.json

### Phase 2: 开放编码（keywords.py）
从评语中提取领导力特征关键词：
- 预置6视角x30+子编码x100+触发词的关键词词典
- 长词优先匹配，避免误配
- 同一关键词被同一评价人多次提及仅计1次（rater_id去重）

### Phase 3: 代表性评语选取（selection.py）
关键词密度法：
- 计算每句命中关键词的密度（命中词数/总词数）
- 先按命中词数>=2筛选，再按密度降序
- 选取Top 2-3条，1:1原始字符串截取

### Phase 4: 主轴编码+画像（encoding.py）
唯一的LLM环节。输入经过Phase 2+3压缩为结构化证据包：
- 每个主轴编码的频次、评价人数、来源分布
- 子编码的频次分布
- 所有命中该编码的评语原文片段（最多8条/编码）

为什么展示所有命中评语而非仅代表性格言？
如果LLM只看到2条代表性格言，画像中的行为描述可能来自通用领导力套话。
展示所有命中评语片段让LLM看到完整行为模式，确保每个描述都有数据出处。

LLM不可用时fallback到规则版，按频次排序输出Top 3优势+Top 2待发展合并。

## 5. 关键设计决策

| 决策 | 选型 | 理由 |
|---|---|---|
| 编码方案 | 混合方案（本地+LLM） | 事实层本地可审计，判断层LLM保证质量 |
| 代表评语选取 | 关键词密度法 | 无需额外依赖，完全确定可复现 |
| LLM输入内容 | 所有命中评语片段 | 防止LLM用通用套话填充行为细节 |
| 来源去重 | rater_id级去重 | 同一评价人仅计1次原则 |
| 画像语言 | 行为素描（非标签列表） | 让读者能看见自己的管理者形象 |
